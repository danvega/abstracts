# From Workflows to Agents: Building Agentic Systems on the JVM

**Format:** Session

## Abstract

Ask five developers what an agent is and you'll get five different answers, but a useful distinction has emerged: in a workflow, your code owns the control flow; in an agent, the model does. In this session we'll make that concrete by building the full progression from workflows to agents with Spring AI.

We'll start with deterministic workflows such as chaining and routing, where your application remains in control. Then we'll give the model more responsibility by adding tools, an agent loop, state, and reusable skills. Finally, we'll explore how agents can delegate work to specialized sub-agents.

Along the way, we'll see what can go wrong when the model gets more control: runaway loops, bad tool choices, rising costs, and hard-to-debug decisions. We'll add practical guardrails including iteration limits, budgets, observability, and human checkpoints.

You'll leave knowing when a workflow is enough, when an agent is justified, and how to build both on the JVM.
